| P-023 | **Commandes git cleanup non-idempotentes polluent le terminal** dans un flux parallélisé à cause de 4 causes concurrentes : (1) auto-prune du runtime sur `.claude/worktrees/agent-<id>` dès que l'agent libère son lock → `git worktree remove` retourne "not a working tree" ; (2) `gh pr merge --delete-branch` supprime la branche locale track → `git branch --delete` retourne "branch not found" ; (3) tentative de remove pendant que l'agent n'a pas encore rendu son rapport → "Permission denied" ; (4) `git branch --delete a b c` s'arrête au premier argument absent. Résultat : erreurs inoffensives mais polluantes à chaque cycle de merge, masquent les vraies erreurs, font douter le Commanditaire. Signalé le 2026-04-18 : « Je vois des shell qui échouent ». | Session 2026-04-18 matin : 9 PR mergées en série avec 3-4 agents parallélisés. Chaque cycle de cleanup produisait 2-3 erreurs visibles dans le terminal sans conséquence réelle — l'état final était toujours propre. Volume cumulé : ~20 erreurs sur la journée. | Adopter le pattern `<commande> 2>/dev/null \|\| true` systématique sur toutes les commandes de cleanup git idempotentes. Testé en direct sur PR #35 merge (2026-04-18) : zéro bruit, état final propre. | **Règle permanente** (LL-027) — **Pattern idempotent obligatoire sur toute commande git de cleanup post-merge** : `git worktree remove -f -f <path> 2>/dev/null \|\| true`, `git branch --delete --force <name> 2>/dev/null \|\| true`, `git worktree prune` (déjà idempotent). Ne **jamais** appeler ces commandes sans suppression d'erreur dans un flux agent parallélisé. Les vraies erreurs (permissions filesystem, corruption .git) remontent via un canal séparé — les "not found" / "not a working tree" sont des faux positifs dus à la concurrence gh/runtime/manual. | Résolu |
