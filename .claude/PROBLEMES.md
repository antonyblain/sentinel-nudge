Détecté au test M7 sur 3 sites avec le même mot de passe : saucedemo fonctionnait (même session SW), mais practicetestautomation échouait car le SW avait été reboot entre les deux (recharge extension), régénérant la clé. | Diagnostic M7 : logs SW montrant 3 auto-régénérations de clé successives (20:24, 20:34, 20:39) malgré le fix P-016 — la clé était sauvegardée mais pas persistée. `success: true, action: skip, reason: no_reuse` alors que le même hash existait en base. | (1) `loadCryptoKey()` : gère désormais 2 formats — `Array<number>` (nouveau, JSON-safe) et `ArrayBuffer` (legacy). Vérification de taille (32 octets pour AES-256). Retour `null` si format invalide → auto-régénération. (2) `onFirstInstall()` : conversion `ArrayBuffer → Array.from(new Uint8Array(keyMaterial))` avant `storage.local.set`. (3) Auto-régénération SW : idem. | **Règle permanente** — `chrome.storage.local` ne supporte QUE les types serializables JSON (string, number, boolean, null, array de ces types, object plain). **Jamais** stocker directement : ArrayBuffer, Uint8Array, Blob, Date, Map, Set, CryptoKey, Promise.
