### Verdict release v1

- [ ] **AUTORISEE** — Tous les 12 scenarios P0 en Pass (Skip documente si pre-condition impossible)
- [x] **BLOQUEE** — Au moins 1 scenario P0 en Fail ou Skip non documente

> **Motif BLOQUEE** : 2 scenarios P0 en FAIL reproductibles documentes — INC-001 (Google `/challenge/pwd` : M7 ne capte pas la soumission, champ orphelin + bouton Suivant non capte) et INC-006 (LinkedIn `/login` : M7 ne capte pas le submit AJAX moderne). Ces deux defauts touchent des sites cles de cyber-hygiene et invalident la promesse fonctionnelle principale de l'extension (alerter sur reutilisation de mot de passe sur sites multi-etape / SPA). MEP v1 reportee a la livraison des correctifs (TACHE-221 + TACHE-223).

### Synthese technique pour le sprint correctif

**Sites OU M7 fonctionne nominalement** (validations) : github.com (form classique, submit DOM standard), Microsoft `login.live.com` (form `<form>` + submit detecte via mutation observer), fixture React useEffect locale.

**Sites OU M7 echoue** (bugs P0) :

1. Google `accounts.google.com/signin/v2/challenge/pwd` (INC-001) — input password orphelin + bouton « Suivant » qui ne declenche pas le fallback Enter+click ;
2. LinkedIn `linkedin.com/login` (INC-006) — submit AJAX moderne (`event.preventDefault()` + `fetch()`) qui ne declenche pas l'event submit DOM classique.

**Defauts UX P1 a corriger** :

- INC-003 : overlay M9 force-mot-de-passe affiche a tort sur ecran de connexion Google + chevauche les elements adjacents ;
- INC-008 : spam de logs UC-05 (27 mutations identiques en 17s) + faux positif tracking M7 sur input recherche.

**Defauts documentaires a corriger (bump protocole v2.1)** :

- INC-002 : format des logs (JSON structure vs « Sentinel Nudge XXX: » obsolete) ;
- INC-005 : toast « Nouveau site » decrit mais non implemente ;
- INC-007 : snippet `chrome.runtime.sendMessage` depuis SW console bugue ;
- INC-009 : TC-M9-01 « detection saisie IBAN » decrit comportement non implemente.
